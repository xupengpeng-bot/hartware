# meter_epoch / counter_reset 合同

更新时间：2026-04-11

## 1. 本次只定义 4 件事

本文件只定义：

- 短码
- 触发时机
- 示例包
- 去重规则

不在本文件中展开：

- 平台订单逻辑
- 退款逻辑
- 启动补发逻辑
- 阀门逻辑

## 2. 唯一目标

平台必须能区分：

- 这次累计量是否和上一次连续
- 如果不连续，是因为什么原因
- 这次不连续事实是否已经上报过

因此设备必须提供两层信息：

1. 持续携带 `meter_epoch`
2. 在发生计量不连续时，主动上报一次 `counter_reset` 事实事件

## 3. 短码

### 3.1 字段短码

- `me`：`meter_epoch`

定义：

- `me` 是设备侧维护的计量世代号
- 类型推荐为无符号递增整数
- 只要计量连续性被破坏，就必须变更 `me`

### 3.2 事件短码

- `ER.p.ec = "crs"`：`counter_reset_event`

定义：

- `crs` 只表示一件事：当前计量链已经进入新的世代
- 平台看到 `crs` 后，必须认为旧世代累计量和新世代累计量不能直接拼接结算

### 3.3 原因短码

`ER.p.rc` 当前定义为：

- `rbt`：设备重启
- `clr`：计数器清零
- `mtr`：换表
- `abr`：异常恢复后确认计量不连续

## 4. 触发时机

### 4.1 设备重启

触发规则：

- 设备每次重启后，`me` 必须变化
- 启动完成后，应尽快生成一条 `crs/rbt`

要求：

- 先变更 `me`
- 再补发 `counter_reset` 事实
- 后续 `HB / SS / QS:qem` 都必须带新的 `me`

### 4.2 计数器清零

触发规则：

- 只要设备本地确认累计运行秒、累计水量或累计电量被清零
- 立刻变更 `me`
- 立刻上报 `crs/clr`

要求：

- 不允许等到下次启动时再报
- 不允许只改数值不报事件

### 4.3 换表

触发规则：

- 只要设备确认当前计量表已更换
- 或表地址、表身份、表序列特征发生了“不能视为同一块表”的变化

要求：

- 立刻变更 `me`
- 立刻上报 `crs/mtr`

### 4.4 异常恢复后计量不连续

触发规则：

- 设备异常恢复后，发现当前累计量与异常前保存快照不连续

典型情况：

- 断电恢复
- 采集模块重置
- 电表离线恢复后累计量回退
- 本地恢复时确认电量/水量/运行秒无法与上次快照连续衔接

要求：

- 立刻变更 `me`
- 立刻上报 `crs/abr`

### 4.5 联网恢复

触发规则：

- 如果 `crs` 事件产生时设备离线
- 联网恢复后只允许补发这条事实事件

要求：

- 只补发 `crs` 事实
- 不补执行旧 `spu`
- 不补重放旧启动动作

## 5. 必须带 `me` 的消息

当前建议至少这些消息携带 `me`：

- `HB`
- `SS`
- `QS:qem`
- `ER(ec=crs)`

最小要求：

- 只要设备已有有效计量上下文，`HB / SS / QS:qem` 就应带 `me`

## 7. 去重规则

### 7.1 一次世代变化，只报一次

规则：

- 每发生一次新的 `me` 变化，只允许生成一条 `crs` 事实

实现建议：

- 持久化保存当前 `me`
- 持久化保存 `last_reported_counter_reset_epoch`

只有当：

- `me != last_reported_counter_reset_epoch`

时，才允许生成并补发 `crs`

### 7.2 同一次事件只报一次

规则：

- 同一次“重启 / 清零 / 换表 / 异常恢复不连续”只能对应一次新的 `me`
- 同一个 `me` 不允许重复生成多条不同原因的 `crs`

建议：

- 一个新世代只保留一个首要原因
- 原因优先级建议：
  - `mtr`
  - `clr`
  - `abr`
  - `rbt`

解释：

- 如果同一次恢复中同时检测到“重启”和“换表”，应优先按 `mtr` 上报，不再额外重复报 `rbt`

### 7.3 离线补发只补事实

规则：

- 离线期间产生的 `crs` 可以进入 pending
- 联网恢复后只补发这条 `crs`
- 不补发旧启动命令
- 不补执行旧 `spu`

### 7.4 快照多次上报不算重复事件

规则：

- `HB / SS / QS:qem` 中重复携带同一个 `me` 是允许的
- 这不算重复事件
- 重复事件只针对 `ER(ec=crs)` 判定

## 8. 平台联调唯一口径

平台请按以下方式理解：

- `me` 用于判断累计量是否仍属同一连续计量世代
- `crs` 用于判断“为什么进入了新世代”
- 看到新的 `me` 后，不得把旧 `me` 和新 `me` 的累计量直接拼接
- 联网恢复后，设备只补事实，不补旧启动
