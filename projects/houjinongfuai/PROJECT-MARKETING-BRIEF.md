# Houjinongfuai Project Marketing Brief

Status: active
Audience: PM, marketing strategy engineer, AI agents
Purpose: provide one stable project-level source for marketing positioning, audience split, core advantages, and proof points.

## Product positioning

This project is not a generic agriculture platform.

Phase 1 is positioned as an irrigation operation system that closes:

- project business operations
- field maintenance operations
- automatic dispatch and warning
- cost accounting and audit

## Core value proposition

The system helps irrigation projects move from fragmented manual coordination to:

- project-level operational visibility
- block-level dispatch and accounting
- explainable automatic scheduling
- auditable runtime and billing
- maintainable data and device governance

## Core advantages

### 1. Business closed loop, not just device monitoring

The project connects:

- project management
- block operations
- runtime sessions and orders
- maintenance and alerts
- electricity metering and cost allocation

This is stronger than a dashboard-only or device-only solution.

### 2. Block-level operation and dispatch

The block is treated as a real dispatch and accounting unit.

This makes the system better suited to operational management than project-wide coarse reporting alone.

### 3. Automatic scheduling with explanation

The target is not just "automation happened".

The project emphasizes:

- scheduling result explanation
- warning interpretation
- history replay
- UAT simulation

This is valuable for customers who need trust and controllability.

### 4. Field reality and model reality are connected

The project links:

- DWG or model initialization
- field data entry
- formal ledger truth
- dashboard and scheduling usage

This reduces the gap between office configuration and field execution.

### 5. Auditable and finance-aware

The system is designed with:

- runtime audit
- billing traceability
- metering-point-based cost accounting
- high-risk action control

This matters for operators and investors, not just technicians.

## Primary audiences

### `project_operator`

Cares most about:

- whether the project can run stably
- whether scheduling becomes easier
- whether costs and income are clearer
- whether multiple blocks can be managed without chaos

Message emphasis:

- project operating efficiency
- fewer manual decisions
- visible block-level operations
- clearer accountability

### `operations_and_maintenance`

Cares most about:

- field problem handling
- alerts and work orders
- equipment and asset traceability
- whether the field truth matches the system truth

Message emphasis:

- field maintenance closure
- asset and device clarity
- warning and work-order linkage
- easier problem localization

### `finance_or_investor`

Cares most about:

- power cost visibility
- block and project accounting
- revenue-cost-gross-margin clarity
- whether decisions are auditable

Message emphasis:

- metering-point-based cost accounting
- project and block cost structure
- auditable runtime and billing chain

### `government_or_platform_owner`

Cares most about:

- standardization
- controllability
- data governance
- expansion potential

Message emphasis:

- structured object model
- permission and audit baseline
- scalable architecture direction
- ability to extend from project to wider regional governance later

## Typical proof points

- Project > Block > Asset > Device > Metering > Runtime > Cost chain is explicit
- automatic scheduling is a first-class product direction
- dashboard is tied to dispatch and warning, not decoration only
- cost accounting is built on metering points, not rough estimates only
- UAT and simulation are treated as product capability, not an afterthought

## Typical objections to prepare for

### "Is this only a dashboard?"

Answer direction:

- no, the dashboard is only one layer
- the project includes operational objects, runtime sessions, orders, work orders, cost accounting, and audit

### "Is this just device monitoring?"

Answer direction:

- no, the system treats projects and blocks as business units
- device data feeds operational and financial closure

### "Will automation become uncontrollable?"

Answer direction:

- the project emphasizes explainable scheduling, warning interpretation, history replay, and auditability

### "Can field reality and model reality stay aligned?"

Answer direction:

- the project explicitly supports field entry, model versioning, and formal truth synchronization

## Marketing material rule

Marketing materials should not claim:

- full nationwide deployment scale unless real evidence exists
- fully closed real-device simulator automation unless delivered
- solved hardware execution if the current milestone is still backend- or UAT-led

Prefer strong but provable claims.
